# РОЙ — паспорт проекта

Версия на 05.10.2026: **1.2** (раздел 14). Сессия 05.10: игра подготовлена к переносу на GitHub Pages как приложение (PWA): манифест, иконки, service worker, работа без сети, плашка «Доступна новая версия». Шмель и личинка **окончательно отменены** пользователем — не предлагать и не делать. Этот файл нужен, чтобы в новом чате не пересказывать историю работы над игрой.

## 1. Что это
Браузерная настольная игра для двух игроков на поле из шестиугольников. Вся игра в одном файле `index.html` (около 125 КБ): стили, разметка и JavaScript внутри, графика SVG, звук синтезируется Web Audio API. Внешних зависимостей нет. Рядом лежат файлы приложения: `sw.js`, `manifest.webmanifest`, `icons/` (раздел 15).
- **Главная копия — репозиторий GitHub** (с версии 1.2). Править нужно файлы из репозитория. Сайт публикуется через GitHub Pages автоматически после коммита в `main`.
- Старый артефакт Claude https://claude.ai/artifact/B1bcLH38UBiYeJLpgjRYVe («РОЙ», иконка 🍯) остался на версии 1.1. Без просьбы пользователя его не обновлять. В проекте Claude копия игры лежит как `roy.html` — это тот же `index.html` из репозитория.
- Игра называется РОЙ. Слово «улей» — финальное название клеточной зоны во всём тексте игры (пробовали «гнездо», пользователь откатил, вопрос закрыт). Ключи `localStorage` (`ulei-*`) и внутренние имена (`G.hive` и т.п.) от названия не зависят.
- Язык интерфейса: русский. Пользователь общается по-русски. Английский язык и головоломки запланированы отдельными обновлениями (раздел 12).

## 2. Правила игры
- Поле: всегда 8×9. Два «улья»: верхний (игрок 0) и нижний (игрок 1). Форма улья зависит от режима фигур (раздел 3): треугольная (без королевы, буфер 1 клетка от края), «цветок» из 7 клеток (с королевой) или прямоугольный блок 2×6 (рой против роя).
- Цель раунда: перевести все свои фигуры в улей соперника. Побеждает тот, кто сделает это первым.
- **Пчела** (звезда) ходит на любую из 6 соседних свободных клеток.
- **Трутень** (треугольник) ходит только на свободную клетку, на которую указывают его вершины. Направление (`d`: `up`/`dn`) само не меняется (есть доп. правило «Разворот»). Каждый трутень остаётся на клетках одного класса (`x%3`), поэтому при расстановке проверяется досягаемость (`feasible`).
- **Королева** (режимы «С королевой», «Рой против роя»): ходит как пчела, может перепрыгнуть через соседнюю фигуру на свободную клетку за ней. Вместо хода может толкнуть соседнюю фигуру (`pushDests`/`doPush`, только находясь в клетке любого улья). При расстановке меняется местами с любой своей фигурой. Королева не центрируется принудительно. Центральные клетки улья помечены гравировкой короны (`queenMarkSVG`/`G.ctr`) — это ориентир.
- В режиме «Без королевы» первая пчела, дошедшая до чужого улья, становится королевой (`maybeConvert`, `G.queenMade`).
- За ход двигается одна фигура. Нельзя ходить одной фигурой два хода подряд, если ход есть у другой (кроме доп. правила).
- Ничьи: тройной повтор позиции (`posSig`/`checkRepeat`/`G.rep`), нет ходов ни у кого, **40 ходов без прогресса** (`NP_LIMIT`).
- Досрочное поражение при безнадёжной позиции (`checkHopeless`): за компьютер решает игра, человеку предлагается «Признать поражение» или «Играть дальше».
- После раунда: «Продолжить с этой расстановкой» (ульи меняются местами, недоставленные фигуры проигравшего случайно занимают свободные клетки, первыми ходят проигравшие) или «Начать заново с расстановки».

## 3. Настройки, режимы, правила
Меню «Установки», вкладки: Игра, Настройки правил, Правила, Дизайн, Звук. Внизу кнопки «Как играть» и «Об игре и статистика».
- **Соперник:** Компьютер (по умолчанию) / Человек.
- **Режим игры:** Классический (по умолчанию, до 3 раундов) / Свободный.
- **Масштаб роя** (`figMode`/`selFig`: `'none'|'queen'|'swarm'`): Без королевы (6 фигур) / С королевой (по умолчанию, 7) / «Рой против роя» (12: 4 королевы, 4 пчелы, 4 трутня, улей 2×6, классы клеток ровно 4/4/4).
- **Доп. правила:** свободный вход/выход, ходить одной фигурой подряд, «Разворот» трутня, «Заморозка» (`RULES.freeze`, `q.frz`/`q.exp`, `applyFreezeTransition`).
- **Сложности ИИ в меню нет** — один уровень (раздел 8).

## 4. Экраны
1. Заставка: гравировка «РОЙ», выбор дизайна, «Полный экран» (скрыта в установленном приложении), «Продолжить партию»/«Новая игра» (или «Начать»), «Выход», «Звук».
2. Меню «Установки» — раздел 3.
3. Игровой экран: заголовок, счёт и режим, статус хода, поле, кнопки. В фазе игры: «Отменить ход» (только против компьютера) и «Подсказка», затем «Установки», «Начать заново», «Полный экран», «Отразить экран», «Музыка».
4. Оверлей победы (`winFlashHTML`, `#winFlash`) — только на реальную победу, убирается кликом.
5. Обучение «Как играть» (`#tut`) и экран итогов матча (`#matchEnd`).
6. Плашка обновления `#upd` сверху экрана: «Доступна новая версия игры» → «Обновить» / «Позже» (раздел 15).
7. Названия игроков по дизайну: «тёмные/светлые» (дерево, соты), «фиолетовые/оранжевые» (космос).

## 5–7. Дизайны, звук, адаптация
Дерево/соты/космос (`cellSVG`, `pieceWood/Honey/Space`), три музыкальные темы, звуки хода. Адаптация под телефон, полный экран. В 1.1 перерисованы деревянные фишки (`pieceWood`): скошенный обод (градиенты `wr0`/`wr1`), лицевая сторона (`tk0`/`tk1`), годичные кольца с обрезкой по `wclip`, блик и тонкое внутреннее кольцо. Гравировка тонкая, 0.9 px (`engrave(..., sw=.9)`), масштаб значка 1 / 0.96 / 0.88 (пчела / трутень / королева). Пользователь просил «изящно, в стиле проекта». Прежний вид с толстыми линиями не возвращать.

## 8. Устройство кода (для правок)
- Геометрия: «удвоенные» координаты (`x,r`), `key(x,r)`, соседи (±2,0),(±1,±1). Ульи: `T0`/`TY_T`/`TY_B`, `QT`/`QB`/`QTY_*`, `SWT`/`SWB`/`SWTY_*`. Параметр сетки `f=1` только для «с королевой».
- **ИИ.** `bestMove(p)` — общий поиск лучшего хода для любого игрока: альфа-бета `ab()` + оценка `ev()`/`cost()`. `aiMove()` = `bestMove(1)` + применение хода. Подсказка игроку использует тот же `bestMove(G.turn)`.
- `aiDepth()`: `if(G.swarm) return 2; n = недоставленные фигуры обоих; return n<=6 ? 3 : 2;` — это защита от долгого хода, а не «сложность». Не трогать.
- Штраф за скучивание в чужом улье (`ev()`, `over`) = 14. В `ev()` множество `oc` включает все свои фигуры внутри чужого улья. `repPen(o)` на верхнем уровне `bestMove`: штраф 4 за каждое прошлое появление позиции.
- Отмена хода: `pushUndo()` вызывается перед `doMove/doPush/doTurn` хода человека (только `vsAI`, ход игрока 0). Снимок — JSON полей `UNDO_KEYS` + фигуры + `G.rep`, стек `G.undo`. `undoMove()` снимает ход человека вместе с ответом ИИ. Стек очищается в `init()` и `nextRound()`, в сохранение не пишется.
- Подсказка: `showHint()` → `G.hint={id,k:'move'|'turn'|'push',x,r,tx,tr}`, отметки `hintMarkSVG`, `hintColor`, CSS `.hint-mk`.
- Сохранение партии: `saveGame()` на каждом `render()`, ключ `ulei-save`, формат `{v:1,...}`. Статистика `ulei-stats`, обучение `ulei-tut`, настройки `ulei-theme/-music/-sfx/-sfxstyle/-vol/-style`.
- `VERSION='1.2'` (и такой же `VERSION` в `sw.js`).
- **Полный экран:** `standalone` — игра запущена как установленное приложение. Тогда `fsOk=false` и кнопки «Полный экран» нет. В браузере `fsOk=true`: если Fullscreen API недоступен (iPhone), включается замена `pseudoFS` (класс `body.fs`), выход через «Опции» → «Оконный режим».

## 9. Решения пользователя, которые нельзя ломать
Направление трутней, поле не разворачивается при продолжении/вдвоём, названия кнопок, режим «Битва» не возвращать, «улей» не переименовывать, цвет «Сот» светлый, поворот телефона только в игре, музыка без паузы, поле всегда 8×9, дефолтные настройки. Кроме того:
- Королева не центрируется принудительно и свободно переставляется в расстановке.
- Один уровень ИИ, переключатель сложности не возвращать. Адаптивную глубину не трогать.
- «Рой против роя»: улей 2×6, королевы по краям — не менять без обсуждения.
- Оверлей победы — только на реальную победу, убирается только кликом/тапом.
- Кнопку «Выход» не трогать.
- Порог ничьей без прогресса — 40 ходов.
- **Шмель и личинка отменены навсегда** (решение 02.10.2026). Повтор партии (просмотр ходов) — не нужен.
- Отмена хода и подсказка в статистике никак не учитываются и не ограничены (решение 02.10.2026).
- Обновление у игроков — только по кнопке «Обновить», без принудительной перезагрузки посреди партии (решение 05.10.2026).

## 10. Известные проблемы и идеи
- «Выход» не может закрыть вкладку — оставлено как есть.
- Открыто: проверка на настоящем телефоне — установка на главный экран, работа без сети, плашка обновления (делает пользователь).
- При переезде на новый адрес сохранения, статистика и настройки начинаются с нуля (своё хранилище у каждого адреса). Это ожидаемо.

## 11. Как проверять изменения
- Синтаксис: вырезать содержимое `<script>` в .js и `node --check`; `node --check sw.js`.
- Локальный сервер: `python3 -m http.server` (service worker не работает с `file://`).
- Playwright: Chromium в `/opt/pw-browsers/chromium`, node-скрипт с `require('playwright')` (`NODE_PATH=$(npm root -g)`), состояние читать через `page.evaluate`. Оверлеи появляются с анимацией 0.3–0.4 с.
- Проверка приложения (1.2): дождаться `navigator.serviceWorker.controller`, `ctx.setOffline(true)` + перезагрузка → игра открывается. Обновление: поднять `VERSION` в копиях `sw.js`/`index.html` на сервере → `swReg.update()` → появляется `#upd` → клик «Обновить» → страница перезагружается с новой версией, старый кэш удалён, `resumeGame()` восстанавливает партию.
- Замер времени хода ИИ обязателен при новой геометрии/фигурах. Замеры 1.1 (первый ответ): без королевы ~50 мс, с королевой ~120 мс, рой ~600 мс; в концовке роя ~200 мс.

## 15. Приложение и выпуск обновлений
- `sw.js`: при установке скачивает все файлы из `FILES` в кэш `roy-<VERSION>`; страница и файлы отдаются из кэша (игра работает без сети). Новая версия ждёт (`waiting`), пока игрок не нажмёт «Обновить»: страница сохраняет партию, шлёт `skipWaiting`, после `controllerchange` перезагружается. Старые кэши `roy-*` удаляются при активации.
- Браузер сам проверяет `sw.js` при каждом открытии; дополнительно `swReg.update()` раз в час и при возврате во вкладку.
- **Чек-лист выпуска:** правки в `index.html` → поднять `VERSION` одинаково в `index.html` и `sw.js` → новые файлы добавить в `FILES` → коммит в `main` → тег `vX.Y` в Releases → обновить этот паспорт. Без нового `VERSION` в `sw.js` установленные копии обновление не увидят.
- Совместимость: ключи `ulei-*` не переименовывать. При смене формата `ulei-save` поднять `v` и добавить перевод старого формата.
- Все пути относительные (`./`), поэтому игра работает и по адресу вида `ИМЯ.github.io/roy/`.
